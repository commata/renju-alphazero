## 1. 진단이 보인 것 (요약)

- 기본 GPU 설정에서는 같은 trainer를 같은 입력·설정·지문으로 다시 돌려도 손실이 step 21부터, 평가 곡선이 평가 29부터 달라진다. 크기와 시작 지점이 재현 gate의 차이와 같다.
- 결정론 설정(`use_deterministic_algorithms`, cuDNN deterministic, `CUBLAS_WORKSPACE_CONFIG=:4096:8`)에서는 반복이 비트 단위로 같다. 기존 trainer와 새 trainer(replay off, 진단 off)도 비트 단위로 같다.
- 결정론 설정에서 진단 연산을 켠 실행과 replay를 켠 실행은 아직 없다.
- 그래서 "기본 설정 실행이 과거 c2 기록과 1e-6 안에서 같다"는 조건은 이 환경에서 같은 코드도 통과를 보장하지 못한다. 반면 "현재 환경에서 두 trainer가 같은 계산을 한다"는 결정론 설정에서 정확 일치로 직접 확인할 수 있다.

## 2. 제안

### A. 과거 c2 재현을 참고 기록으로 분리한다

- 새 trainer 실행을 c2 기록과 비교한 결과는 **기록만 하고 판정하지 않는다.**
  - 기록 항목: 평가마다의 차이, 그 최댓값, 처음 다른 평가, eligibility와 선택 step이 같은지
- 수치 계산 전에 정해지는 항목은 계속 **정확 일치를 요구한다.**
  - 입력 SHA(cycle 행, H3, cache 텐서), parent·teacher 신원
  - total steps 96, steps per epoch 48, warmup 5, 평가 step 목록
  - 학습 설정. 수치 설정은 c2와 같되, 결정론 3항목만 다르다(C를 채택하는 경우).
- eligibility와 선택 step은 곡선 값에서 나오는 수치 결과이므로 참고 기록에 둔다(권장).
  - 다른 안: 기존 계약대로 정확 일치를 계속 요구한다. 이번 10회는 모두 c2와 같았지만, 결정론 실행은 c2와 평가 10부터 값이 다르다. 그래서 이 안에서는 수치와 무관한 이유로 멈출 수 있다.

### B. 현재 환경 동등성 gate (판정)

- 모든 실행은 결정론 설정으로, 각각 별도 프로세스에서, 같은 입력·seed 20261024·c2 설정으로 돈다.

| 실행 | trainer | 옵션 |
|---|---|---|
| E1 | `h7c_train.train_policy` (기존) | 없음 |
| E2, E3 | `h7r_p1_train.train_policy` (새) | replay off, 진단 on (본학습 arm C가 도는 방식 그대로) |
| E4, E5 | 새 trainer | replay on, μ 0.5 (arm T가 도는 방식 그대로) |

- 판정(모두 **정확 일치**, 허용 오차 0)
  - G1 결정론: E2 = E3, E4 = E5
  - G2 동등성: E1 = E2. 기존 trainer에 없는 진단 항목(RenjuNet val KL)을 빼고 비교한다.
  - 비교 항목: step별 손실, 지문 4종, 모든 평가의 val·guard 값, eligibility, 선택 step, 선택 state 해시, 고정 국면 log-확률 해시
- 허용 오차 0은 관측값에서 뽑은 것이 아니다. "결정론 설정에서 같은 계산을 한다"는 말의 정의다.
  - 진단 연산을 켠 경우(G2)와 replay를 켠 경우(G1의 E4·E5)는 진단에서 시험하지 않았으므로 실패할 수 있다.
- 실패하면
  - 본학습 전에 멈추고, 기록과 로그를 커밋한다.
  - 진단을 끄고 다시 비교하거나, 기준을 낮추거나, 결정론 설정을 끄는 대체 경로는 두지 않는다. 원인 진단을 다시 승인받는다.
- 결정론 구현이 없는 연산 때문에 오류가 나는 것도 실패로 기록한다.
- G1의 E4·E5는 replay 경로가 결정론 설정에서 돌고 반복되는지만 본다. 그 결과로 학습 효과를 읽지 않고, 그 state를 쓰지도 않는다.

### C. 본학습 6회도 결정론 설정으로 돌린다 (권장)

- gate와 같은 설정으로 arm C·T 6회를 돌린다.
  - 도구는 `CUBLAS_WORKSPACE_CONFIG`가 없으면 시작하지 않는다.
  - 실행마다 수치 설정을 기록하고, gate 기록과 같은지 확인한다.
- 이유
  - gate가 확인한 "같은 계산"이 본학습에도 그대로 적용된다.
  - 각 seed 실행이 다시 돌려도 비트 단위로 재현된다. 기본 설정에서는 같은 seed의 반복끼리도 고정 국면 argmax가 약 0.1% 다르다.
- 비용: 진단 10회(결정론 4회 포함)가 약 10분에 끝났다. 실행별 시간은 기록되지 않았으므로 gate 기록에 시간을 남긴다.
- 결과
  - 결정론 설정의 arm C는 c2 checkpoint와 수치가 같지 않다(평가 10부터 다르다).
  - 다만 arm C는 원래부터 c2 checkpoint 자체가 아니라 c2 방법으로 새로 학습한 대조군이다. T와 C는 같은 설정 안에서 비교된다.
- 다른 안: 본학습은 기본 설정으로 둔다. 이 경우 각 seed 실행에 실행 간 변동이 섞이고, 결정론 설정에서 확인한 gate 결과가 본학습에 엄밀히 이어지지 않는다.

### D. 절차

- 새 계약(A1)은 `prepare`부터 다시 거친다. 입력 대조이므로 짧다.
- 순서: prepare → gate(B) → train(6회) → link → Arena. 단계마다 따로 승인받는다.
- 구현 범위(A1 승인 뒤)
  - P1 도구의 결정론 설정과 gate 명령, 참고 기록
  - 새 계약 초안, 테스트, 데스크톱 블록
- 기존 `h7c_train.py`, `h7r_p1_train.py`의 학습 계산은 바꾸지 않는다.
