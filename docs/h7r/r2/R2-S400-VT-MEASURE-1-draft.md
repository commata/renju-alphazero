# R2-S400-VT-MEASURE-1: S50이 수를 가르는 국면에서 S400 탐색 결과가 value 목표로 쓸 만한가 (측정 계약 초안)

- 작성일 2026-11-18. 상태: **초안, 결정 전. 모든 단계 미승인. 도구·계약 JSON 없음.**
- 이 계약은 측정만 한다. 학습, 자유 대국 Arena, champion 변경, MCTS V9, 강화학습 루프 재개는 하지 않는다.
- 결과가 사전 기준(§8)을 충족할 때만 별도의 학습 계약(value 목표만 바꾸는 비교)을 연다.

## 0. 근거

| 기록 | 내용 |
|---|---|
| `docs/h7c/e2/sb_c5_saturation.json` | 같은 H3 + c5로 S400이 S50보다 강했다. 150쌍 확인에서 점수 0.5767, 개선 95% 구간 [+2.5, +12.7]%p, STRONGER. 수당 시간은 50쌍 예산 arm에서 4.94배(S400 arm 단독은 +9.5%p, 하한 0.0, NOT_DETECTED) |
| R2-D1-HEAD-WIDTH-1 (D4 full) | value 예측 손실은 줄었지만(H-dev `DEVELOPMENT_SIGNAL`) H-dev 선택 품질 판독은 `NOT_ESTABLISHED` |
| R2-S400-TRAIN (`4ff2818`) | S400 정책 목표로 학습한 후보: P′ WEAKER(−2.00%p), D′ NOT_ESTABLISHED(+0.46%p). S400 정책 목표의 이득은 입증되지 않았다 |
| R2-D4 (D1 D4 full 기록) | H-dev 15,985국면 중 S50이 tree로 탐색한 국면 7,252개(약 45%). 나머지는 solver·VCF 등 tree 밖 경로 |

- 깊은 탐색은 대국에서 더 강하다. 그러나 그 결과를 학습 목표로 옮긴 두 시도(정책 목표, 넓힌 value head)는 착수 개선으로 이어지지 않았다.
- 그래서 학습 전에 두 가지를 먼저 잰다.
  - 깊게 탐색했을 때 바뀐 선택이 독립 판정에서도 더 좋은가.
  - 그 차이가 S50에서 value 비교가 수를 가르는 국면에 있는가. 그 국면에서 S400의 값이 c5 value 망의 값보다 독립 판정 결과에 더 가까운가.

## 1. 질문

- **Q1 (수)**: 같은 H3 + c5에서 S400과 S50의 선택이 갈리는 국면, 특히 S50의 value 비교가 수를 가르는 국면에서, S400의 수가 Rapfi continuation 판정으로 더 좋은가.
- **Q2 (값)**: 그 국면들에서 S400 루트 값이 c5 value 망의 값보다 Rapfi continuation 결과에 더 가까운가. S400 루트 값은 앞으로 value 목표 후보로 쓸 정의와 같다.
- 답하지 않는 것: 실제 기력, minimax 정답, 학습한 모델의 성능, 승급, V9 진입.

## 2. 표본: H-dev 396판 전체

- R2-D4와 같은 H-dev를 쓴다. 새로 뽑지 않는다.
  - H-dev 계약 `docs/h7r/contracts/R1-HDEV-1.json`(SHA `348fecda98c4…`), binding `9724d878eed4…`, 원본 400판 `93b05a037f20…`, 평가 rows `ed0e4be2a212…`, test tensor `c3b389dad321…`
  - 평가 국면은 R2-D4가 고정한 목록(`docs/h7r/r2/R2-D4-BASELINE-1/eligible.json`, `28f0d48`)과 같은 396판·15,985개 (game, ply)다. warm-up ply 792개는 탐색하되 관측에 넣지 않는다. 기존 probe 제외 4판은 그대로 제외한다.
- 사용 규칙
  - H-dev는 R2-0A, X1, R2-0B, D4, D1 D4에서 이미 본 개발 자료다. 이 계약의 결과는 개발 판독이다. 독립 확인이라고 부르지 않는다.
  - 학습, early stopping, checkpoint 선택에는 쓰지 않는다. 뒤따르는 학습 계약도 H-dev를 학습 자료로 쓰지 않는다.
- 이유: R2-S400-TRAIN의 S400 탐색 기록(c2 train 범위 18,965국면)을 재사용하면 탐색 약 4.5시간을 아낄 수 있다. 그러나 그 국면은 학습 자료이고, 뒤따를 학습 계약과 겹친다. 측정을 학습 자료 밖에서 하려고 H-dev를 쓴다.

## 3. 탐색 조건

| 이름 | 설정 | 역할 |
|---|---|---|
| S50 | frozen TB-V3 / fast5, H3 정책 + c5 value, 기존 S50(`h7c_arena.make_side`) | actor 재현과 기준 선택 |
| S400 | 같은 모델과 검사, tree 예산만 8배(`h7c_budget.make_budget_agent(8, …)`) | 깊은 탐색의 선택과 루트 값 |

- 두 설정 모두 모델 SHA(H3 정책 `efee483284df…`/`5648b7fbe71d…`, c5 value `4e28a62a4a31…`/`1fcb49ead057…`), engine·runtime·source SHA를 실행 전에 대조한다.
- actor 재현은 R2-D4 §5와 같다.
  - 원본 self-play의 ply 전체를 원래 순서로 탐색한다(`h7c_sensitivity.replay_game`의 의미). 색별 agent seed는 `derive_seed(game_seed, color)`로 같다.
  - S50은 모든 ply에서 원본 actor의 engine 수, route, root visits/Q를 재현해야 한다. 하나라도 다르면 실행 오류다(행을 빼지 않는다).
  - S400은 같은 국면, 같은 seed 규칙으로 탐색한다. S400의 수를 이어 두지 않는다(다음 국면은 원본 수순이다).
- 국면마다 기록: 두 설정의 route, engine 수, root visits/Q(`h7c_targets.raw_visits` 형식), tree 예산, 시간. 그리고 H3 정책의 합법 수 1순위와 c5 value 망의 원값.

## 4. 국면 분류 (Rapfi 결과를 보기 전에 고정)

| 집합 | 정의 |
|---|---|
| E | 평가 국면 15,985개 |
| T | E 중 S50과 S400이 모두 tree 경로인 국면 |
| V (value 관여) | T 중 다음 하나라도 만족하는 국면 |
| — V-A | S50의 수가 H3 정책의 합법 수 1순위와 다르다(루트 탐색이 정책 1순위를 뒤집었다) |
| — V-B | S50 루트의 방문 1위와 2위 차이가 루트 총 방문의 20% 이하다(값 비교가 근소한 경합) |

- 동률 처리: 정책 1순위가 여럿이면 (행, 열) 순서의 첫 수, 방문 순위는 엔진의 정렬(방문, Q, 수)을 따른다.
- V-B의 문턱 20%는 이 초안의 제안값이다(§11 결정 사항). 계약 고정 뒤에는 바꾸지 않는다.
- 각 집합의 크기, V-A와 V-B 각각과 겹침, 대국 수를 보고한다.

## 5. 측정 (a): 수

- **관측**: 국면에서 S400과 S50의 engine 수가 다르면 관측 하나 (game, ply, S400 수, S50 수).
  - **주 판독은 V 안의 관측**이다. E 전체와 T의 관측은 보조로 보고한다.
- **판정**: R2-D4 §6의 Rapfi continuation을 그대로 쓴다.
  - 고정 수 뒤부터 양쪽 모두 Rapfi가 끝까지 둔다. 분기마다 새 프로세스. 점수는 고정 수를 둔 쪽 기준(승 1, 무 0.5, 패 0).
  - Rapfi executable·모델·설정 SHA, INFO, rule 4, `max_node=300`, thread 1, 응답 상한 600초는 R2-D4 계약에 등록된 identity와 같아야 한다. 다르면 시작하지 않는다.
  - 같은 분기는 한 번만 실행한다(분기 key: 전체 history, 고정 수, 차례).
  - 모든 continuation을 Game으로 재생해 검증한다.
- **INVALID**: R2-D4 §7을 그대로 쓴다(`h7r-invalid-v1`). 구조적 abnormal_end만 0.5로 정규화하고, 실행 실패는 미해결 분기로 남겨 하한·상한 delta를 따로 계산한다. 미해결 관측이 5%를 넘으면 INCONCLUSIVE. 데이터 오류는 멈춘다.
- **지표**: `delta_i = score(S400 수) − score(S50 수)`, `mean_delta = Σ delta_i / N`(동일 결과는 0으로 포함).
- **함께 보고**: E·T·V 각각에서 수가 바뀐 비율(분모는 그 집합 전체), 좋아진 / 나빠진 / 같은 관측 수, 미해결과 정규화 건수, 대국별 관측 분포, V-A와 V-B 각각의 결과.

## 6. 측정 (b): 값

- **기준 결과 r**: 국면에서 Rapfi가 양쪽을 끝까지 둔 결과, 그 국면의 차례 쪽 점수(승 1, 무 0.5, 패 0). 고정 수 없이 Rapfi가 첫 수부터 둔다(새 분기 종류. 설정·검증·INVALID 규칙은 (a)와 같다).
- **비교하는 값**(모두 차례 쪽 점수 척도 [0, 1]로 바꾼다)
  - `v_c5`: c5 value 망의 원값
  - `v_S400`: S400 루트 값. 루트 자식 Q의 방문 가중 평균이다. 뒤따를 학습 계약의 value 목표 후보와 같은 정의다.
  - 참고: `v_S50`(S50 루트 값, 같은 정의). "탐색 자체"의 효과와 "더 깊은 탐색"의 효과를 나눠 보려는 서술용이다.
  - 부호와 척도 변환(루트 자식 Q는 루트에서 둔 쪽 기준)은 도구 구현 때 기존 경로로 고정하고, 알려진 종료 국면과 S50 actor 기록으로 테스트한다.
- **지표**: 국면마다 `d_j = (v_c5 − r_j)² − (v_S400 − r_j)²`. 양수면 S400 값이 r에 더 가깝다. `mean_d = Σ d_j / M`.
  - r이 한 번의 continuation이라 잡음이 크다. 하지만 기대값으로 보면 `E[d] = (v_c5 − p)² − (v_S400 − p)²`이다(p는 Rapfi가 그 국면에서 낼 기대 점수). 그래서 두 값 중 어느 쪽이 Rapfi의 기대 점수에 가까운지를 짝 비교로 잰다. minimax 정답에 대한 측정은 아니다.
- **범위**: 주 판독은 V 전체 국면(수가 갈렸는지와 무관). 보조로 T 전체.
- **미해결 r**: r ∈ {0, 1} 두 경우로 d의 하한·상한을 계산한다(구조적 정규화는 0.5). 미해결 국면이 5%를 넘으면 INCONCLUSIVE.
- **함께 보고**: `v_S50` 대비 같은 지표, H-dev 기존 value label(결과·증명) 대비 오차(참고), 평균 절대 차이 `|v_S400 − v_c5|`.

## 7. 통계

- source-game cluster bootstrap 20,000회, percentile. 396판의 같은 multiplicity를 모든 지표에 쓴다. bootstrap seed는 계약 고정 때 정한다(기존 계약과 겹치지 않게).
- 판독(각 주 지표 하나씩, 단측 α 0.025 = 양측 95% 구간)
  - **BETTER**: 하한 지표(미해결을 불리하게 둔 값)의 구간 하한 > 0
  - **WORSE**: 상한 지표의 구간 상한 < 0
  - **INCONCLUSIVE**: 그 밖이거나 최소 조건 미달
- 최소 조건(지표마다): 관측 100개 이상, 관측이 있는 대국 30판 이상, 미해결 5% 이하, actor 재현·identity·Game 재생 통과, bootstrap 분모 0 회차 없음.
- 두 주 판독(a, b)은 §8의 진입 규칙에서 둘 다 성립해야 하는 교집합 주장이다. 그래서 각각 95% 구간으로 판정한다(intersection–union). 보조 지표는 보고만 하고 판독하지 않는다.
- 계획값(판정 문턱 아님): T 국면 약 7,200개 중 수가 갈리는 비율을 20–30%로 두면 V 안의 관측은 수백에서 천여 개다. smoke 뒤에 실제 비율로 예상 정밀도를 다시 계산해 기록만 한다. 기준과 표본은 바꾸지 않는다.

| (a) 수, V | (b) 값, V | 다음 |
|---|---|---|
| BETTER | BETTER | value 목표만 바꾸는 학습 계약 초안을 연다: 학습 행·정책·모델 구조·S50 예산을 c5와 같게 두고, value 목표만 S400 루트 값(정의 §6)으로 바꾼다. 독립 확인 Arena에서 기력 우위가 입증될 때만 강화학습 루프 재개를 검토한다 |
| BETTER | 그 밖 | 학습 계약을 열지 않는다. 깊은 탐색은 그 국면에서 더 좋은 수를 고르지만, 그 값이 더 나은 value 목표라는 근거는 없다 |

- 결과를 보고 V의 정의, 문턱, 표본, 판정 설정을 바꾸지 않는다. 바꾸려면 새 계약이다.

## 11. 결정이 필요한 사항

1. V-B 문턱: 방문 1·2위 차이 ≤ 루트 총 방문의 **20%**(제안). 더 좁히면 V가 작아지고, 넓히면 값이 덜 관여하는 국면이 섞인다.
2. (b)의 기준 결과: **Rapfi continuation(제안)**. H-dev 기존 value label(대국 결과·증명)은 참고로만 보고한다. 기존 label은 c5 actor 대국에서 나와 독립 판정이 아니다.
3. 최소 조건: 관측 100개, 대국 30판(제안). R2-D4의 20개 / 10판보다 높다. 비교가 하나라 seed 간 보정은 없다.
4. bootstrap seed와 계약 id(`R2-S400-VT-MEASURE-1` 제안).
