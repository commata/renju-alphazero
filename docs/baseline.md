- 기준 엔진 커밋: `e4a64c28d994b5c38a7f085f25982052e9729cbc`

## 측정 방법

```bash
python scripts/run_baseline.py --games 20 --seed 42
python scripts/benchmark_engine.py --iterations 100 --games 10 --seed 42 --profile
```

대결마다 20판을 진행하며 매 판 새 보드와 에이전트를 생성한다. master seed의
`Random.getrandbits(64)`를 흑, 백 순서로 호출해 판별 난수 seed를 배정한다.
따라서 색 교환 대결의 seed 스트림은 **색 슬롯 기준**이며 동일 에이전트의 동일
수순을 강제로 교환하는 개국 대결은 아니다. 전술 후보 선택은 행·열 순으로 고정한다.
각 에이전트의 금수 판단은 현 엔진을 그대로 따른다.

벤치마크의 중반 국면은 seed가 고정된 RandomAgent의 정상 착수로 60/61수를
진행해 만든다. 판 준비와 에이전트 생성은 시간에서 제외한다. `play+undo`의
1회는 두 호출을 합친 한 쌍이며, `legal_moves`의 1회는 합법수 목록 전체 생성이다.
개별 `forbidden_reason` 수치는 출력된 한 좌표의 반복 측정으로 모든 후보의 평균이 아니다.
흑 빈 보드와 백 1수 후 보드는 각각 도달 가능한 개국 상태를 사용한다.

프로파일은 처리량 측정 후 별도 대국(Random seed 42 vs 43)에서 실행한다.
`cProfile`의 누적 시간은 하위 호출을 포함하므로 함수별 값을 더하지 않는다.
프로파일 자체 오버헤드가 있으므로 이 시간으로 실제 games/sec를 계산하지 않는다.
테스트, 대결 평가, 벤치마크는 서로 겹치지 않게 순차 실행한다.

## 프로파일과 병목

별도 Random 대국은 91수이며 프로파일 총 시간은 38.010초였다.
다음 값은 `cProfile`의 누적 시간으로, 하위 호출 시간이 중첩된다.

| 함수 | 호출 수 | 누적 시간(s) |
| --- | ---: | ---: |
| play_game | 1 | 38.010 |
| forbidden_reason | 16381 | 37.977 |
| Game.legal_moves | 181 | 37.898 |
| _open_three | 64872 | 36.312 |
| _fours | 1367024 | 27.984 |
| RandomAgent.select_move | 91 | 19.112 |
| Game.play | 91 | 18.897 |

주요 병목은 **흑 합법수 생성에 필요한 금수 검사**다.
`forbidden_reason`의 누적 시간은 전체의 약 99.9%, `legal_moves`는 약 99.7%다.
특히 열린 삼 판정 `_open_three`가 하위 호출 포함 약 95.5%를 차지했다.
개별 금수 판정은 한 좌표의 비용이고 흑 합법수 계산은 여러 빈칸을 검사하므로,
개별 호출보다 전체 목록 생성에 훨씬 많은 시간이 걸린다.

백의 `play+undo`가 약 134.70ms인 이유는, 현재 `Game.play()`가 착수 후
다음 차례의 합법수 존재를 확인하기 위해 **흑 `legal_moves()` 전체를 호출**하기
때문이다. 중반 흑 목록 생성 135.55ms와 비슷한 비용이다. 반대로 흑 착수 후에는
백 목록을 확인하므로 같은 측정의 흑 `play+undo`는 약 0.275ms였다.
이는 코드 경로와 측정값이 함께 뒷받침하는 해석이며 착수 함수 자체의 시간과
하위 금수 검사 시간을 독립적인 비용처럼 합산하면 안 된다.

엔진 최적화는 수행하지 않았다. 위 기록을 기준으로 다음 단계에서 탐색 호출 수와
비용을 비교할 수 있다. 현재 규칙 범위의 소규모 순수 MCTS 구현으로 넘어갈 수
있으나, 반복 탐색은 이 합법수 계산 비용을 누적해서 지불한다. 또한
[규칙 문서](rules.md)의 재귀적인 삼삼 판정 미구현 한계는 그대로이므로,
공식 렌주 규칙의 완전한 준수를 검증한 것으로 해석하지 않는다.
