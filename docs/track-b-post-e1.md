# Track B 방향: E1 이후 설계 (검토 반영)

작성 2026-10-09. 입력: "E1 이후 설계 방향" 초안(실전 패배 → 사례 축적은 계속하고, 휴리스틱 추가는 E3 이후 제한하는 안).
기준 문서(§번호는 따로 적지 않으면 mcts-v8-teacher.md의 절): [ROADMAP 두 트랙](../ROADMAP.md#두-트랙-2026-10-01), [mcts-v8-teacher.md §12](mcts-v8-teacher.md)(특히 §12.1, §12.18, §12.19, §12.25–§12.27).
전제: **Track B의 목표는 최강 기력의 렌주 AI**다(§12.1 "목적: 최강 기력"). 이 문서는 그 목표에 맞게 초안을 고친다.

## 0. 결론

**큰 방향은 맞다.** 실전 패배를 증명된 사례와 평가 세트로 쌓고, 패배마다 규칙을 붙이지 않는다는 원칙은 유지한다.
다만 초안에는 고칠 곳이 네 가지 있다.

1. **트랙 배치가 저장소 정의와 다르다.** 초안은 H6~H8을 Track A에 두고 solver를 Track A의 teacher·veto로 쓴다.
   §12.1에서 H 단계는 Track B이고, Track A는 solver supervision·teacher 라벨·RenjuNet을 금지한다.
   그래서 초안의 "Track B는 계속 강화, Track A는 고정"은 실제로는 **Track B 안의 두 층**(전술 엔진 / 신경망) 사이의 문제다.
2. **"영구 동결"이 아니라 "주기 단위 동결"이다.** 최강 기력이 목표면 최종 제품은 신경망 + PUCT + 증명 solver다.
   전술 계층 개선을 끝없이 막을 이유는 없다. 문제는 개선이 **학습 데이터 생성 중간에 섞이는 것**이다.
   엔진은 H7 self-play 한 주기 동안 고정하고, 주기 경계에서만 gate를 통과한 변경을 올린다.
3. **self-play 품질은 방어 veto보다 공격 쪽 응징 능력에 더 좌우된다.** 지금 엔진의 자기 공격은 VCT1까지(V8-B)다.
   양쪽이 같은 엔진인 self-play에서는 VCT2 패배수를 둬도 상대가 응징하지 못한다(8411 p22, 웹 `161802`에서 이미 관측).
   H7 엔진에는 E2 상대의 selective VCT2 공격(증명된 WIN만)을 넣는 것이 veto보다 먼저다.
4. **라벨 관점이 틀린 곳이 있다.** 초안 §7의 "veto한 국면 s에 label −1"은 §12.18 계약(둘 차례 관점)과 맞지 않는다(§4).

## 2. 원칙: 주기 단위 동결과 채택 gate

### 2.1 Track B의 두 층

| 층 | 내용 | 버전 |
|---|---|---|
| B-engine | legal/terminal → 증명 승리 → PROVEN_LOSS veto → PUCT, VCF/VCT 모듈(V8-A/B/C, S3-VCT2) | `TB-Engine-vN` (설정 전체를 한 파일에 고정, `s3_vct2_v1.py` 방식) |
| B-net | H3 policy, H6 value, H7 이후 checkpoint | checkpoint SHA-256 |

- 최종 제품과 H8 평가 대상은 **B-net + B-engine 조합**이다.
- self-play 데이터 행마다 `engine_config_hash`, `model_hash`를 남긴다(§12.18 계약에 이미 있음).

### 2.2 동결 규칙

- **H7 한 주기(데이터 생성 구간) 안에서는 B-engine을 바꾸지 않는다.** 예외는 아래 "버그"뿐이다.
- 주기 경계에서만 B-engine 변경을 올린다. 그 사이 발견한 문제는 후보 목록에만 쌓는다.
- replay buffer가 허용하는 엔진 버전 범위를 명시한다(§12.18 H7 provenance와 같은 방식).

### 2.3 B-engine 변경 채택 gate (모두 만족)

1. **증명 건전성:** `unsound_witness` 0, 방어자 응수는 전체 합법수(§12.18 원칙 3). 거짓 PROVEN_LOSS가 하나라도 있으면 채택하지 않는다.
2. **근거는 holdout에서:** dev에서 원인을 찾았으면 판정은 holdout(E1-holdout 또는 새 seed)에서 한다.
3. **빈도:** 같은 실패 유형이 holdout에서 반복돼야 한다(단발 사례는 기록만). 기준 횟수는 E1 결과를 보기 전에 정한다.
4. **기력:** 고정 상대와 짝 비교에서 비열등(점수 차 하한 ≥ −0.05), 그리고 목표 실패 유형의 지표 개선.
5. **비용:** end-to-end 시간 비율 ≤ 1.5.
6. **격리:** 기본값 off 옵션으로 추가, off에서 기존과 같은 착수(§12.18 원칙 1).

### 2.4 새 패배 처리 순서

```
새 패배 → offline 참값 확정(§12.27 방식, 노드 예산만)
 ① 규칙·solver·엔진 버그(잘못된 증명, 금수 오판, 부호 오류)?
      예 → 즉시 수정. 주기 중이어도 고친다. 영향받은 데이터는 engine hash로 찾아 무효화
 ② 증명 범위(VCF/VCT1/VCT2) 안인데 검사하지 않았거나(ROUTE_COVERAGE_MISS)
    검사했지만 선택 규칙 때문에 졌나(BUDGET_AMBIGUITY, K4_MISS, SELECTION_ERROR)?
      예 → B-engine 후보 목록. 다음 주기 경계에서 §2.3 gate
 ③ 상대 강제승을 우리가 응징하지 못했나(공격 쪽 지평선)?
      예 → 공격 모듈 후보(증명된 WIN만). §3
 ④ 더 깊은 지평선(VCT3 이상) 또는 위치적 패배?
      예 → 엔진 규칙을 만들지 않는다. probe·holdout 등록,
           증명된 국면이면 라벨 후보(누출 규칙 적용). B-net과 탐색 깊이가 풀 문제로 남긴다
```

초안과 다른 점: ①에 "증명 건전성"을 명시했고, ②에 선택 규칙 실패를 넣었고, ③을 새로 넣었다.
④에서 VCT3 veto를 만들지 않는다는 결론은 초안과 같다.

## 3. self-play 품질: 응징 능력이 먼저

- 기준 arm은 VCT2 패배가 증명된 수를 두고도 이겼다(8411 p22와 두 교체 국면의 기준 arm, §12.25). 웹 `161802`도 패배 수로 교체한 뒤 이겼다(§12.27). 상대가 강제승을 쓰지 못했다.
- 같은 엔진끼리 두는 self-play에서는 이것이 그대로 value 라벨 오류가 된다. 진 국면이 +1 결과로 들어간다.
- 방어 veto만으로는 막을 수 없다. veto는 자기 수만 거르고, UNKNOWN은 통과시키며, stage 경로는 검사하지 않는다.
- **H7 B-engine에 selective VCT2 공격(증명된 WIN만)을 넣는다.** E2 상대와 같은 모듈이다.
  - E2가 이 모듈의 비용과 착수 품질을 같이 잰다. E2 결과를 H7 엔진 결정에 그대로 쓴다.
  - 공격은 witness가 있는 경우에만 둔다. 거짓 WIN은 없어야 한다(§2.3-1).
- 응징이 들어가면 대국 결과 라벨과 증명 라벨이 서로 덜 어긋난다.

## 4. H6 라벨 보완 (§12.18 계약에 추가)

### 4.1 veto 국면의 라벨 관점

- 국면 s에서 수 m이 PROVEN_LOSS로 veto됐다는 것은 **m 뒤 국면 s′에서 상대가 강제승**이라는 뜻이다.
- 라벨은 **s′(둘 차례 = 상대)에 +1**이다. s에는 라벨이 없다. s의 다른 수가 살아 있을 수 있기 때문이다.
- s에 −1을 붙이는 것은 **s의 합법수 전부가 증명된 패배일 때만**이다(P94 유형).
- 초안의 "state = s, label = −1"은 위 조건을 만족할 때만 맞다.

### 4.2 부호 쏠림

- 싸게 얻는 증명은 대부분 "둘 차례가 강제승"(+1)이다. −1은 모든 합법수를 반박해야 해서 비싸다.
- H6-1 보고(출처·깊이별 ±1 비율)에서 쏠림이 크면 다음으로 균형을 맞춘다: −1 소스(전 합법수 패배 국면, 대국 결과) 가중, 또는 출처별 loss weight.
- D4 증강과 색(흑/백) 균형도 함께 보고한다.

### 4.3 증명과 대국 결과가 어긋날 때

- 증명된 국면은 증명 라벨이 이긴다(mcts-v8-teacher.md §1 "proof label > 탐색 분포 > 대국 결과 z").
- 증명된 패배 지점 뒤로 대국 결과가 반대인 구간(응징 실패)은 `outcome_conflicts_proof`로 표시하고 대국 결과 라벨을 mask한다.
  H6-1 전에 이 규칙을 고정한다.

### 4.4 policy target

- PROVEN_LOSS로 증명된 수에 간 방문은 soft target에서 지운다(mcts-v8-teacher.md §5.2 기존 규칙). veto된 수를 policy가 피하도록 배우는 경로가 이것이다.
- raw visit 분포도 함께 저장해 나중에 비교할 수 있게 한다.

## 5. 장기 방향: value가 solver 예산을 정한다

- 목표 지표는 **같은 시간 예산에서의 기력**이다. solver 호출 수 감소는 결과이지 목표가 아니다.
- PROVEN_LOSS veto와 증명 승리는 끝까지 value보다 위다.
- value가 생기면 바꿀 곳: 고정 K=4와 tree 순서로 정하던 veto·대안 검사 순서를 value·불확실성 순서로 바꾸고, solver 예산을 그 순서대로 준다.
  각각 별도 arm, 같은 시간 비교(§12.18 원칙 4).
- 지연 꼬리(착수 p95 82.9초, 최대 124.4초, §12.27)는 L 트랙으로 따로 다룬다. 시간 제한 대국에서 최강이 목표라면 H8 전에 필요하다.

## 6. 평가

- 내부 상대는 대부분 VCT1까지만 공격한다. VCT2 이상을 응징하는 상대가 없으면 방어 개선이 점수에 안 나온다(§12.25).
  E2 상대를 이후 표준 상대 중 하나로 고정한다.
- (선택) 외부 강한 렌주 엔진을 offline 평가 전용 상대로 쓴다. 학습·튜닝에는 쓰지 않는다. 같은 규칙(흑 첫 수 중앙 고정, 자유 착수)을 지원하는지 먼저 확인한다.
- 웹 대국은 stress test로만 쓰고 승률로 해석하지 않는다(§12.26).
- **배포 제약:** RenjuNet으로 학습한 B-net은 로컬 전용이다(§12.1). "최강 AI"를 공개 배포하려면 RenjuNet 없이 학습한 변형이 따로 필요하다.

  → H7 주기 1 (TB-Engine-v1 고정)

- "FREEZE"를 영구 동결이 아니라 `TB-Engine-v1`(주기 1 동결)로 바꿨다.
- selective VCT2 공격을 H7 엔진 후보로 명시했다.

**2026-10-09 후속.** 이 로드맵의 B 계열은 B1-Champion이다. H8 이후 B1-Matched·B2 비교 실험과 봉인 holdout(Final-1/Final-2)은
